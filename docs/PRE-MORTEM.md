## Tigers（真风险）

### 🚧 T0-1 部署物 ≠ 已验证物（launch-blocking，最高优先）
- **事实**：工作区 100+ 文件改动**全部未提交**（git 被明确推迟）；DEPLOY §3 推荐 `git clone` 部署 → 直接 clone 拿到的是**旧代码**（无 M-1 / L-1~L-4 / informational 修复，无新验收体系）。
- **缓解**：解锁 git → 提交推送 → CI 绿灯（这也正是 ASSESS S10 的条件项）→ 再部署；若坚持 scp 口径，须 scp**当前工作区**并在服务器复跑 `deploy.sh --verify`。
- **Owner**：你（解锁）+ 我（执行） · **期限：部署前 —— 硬门槛**

### 🚧 T0-2 公网开放注册 = 内容污染面（launch-blocking）
- **事实**：注册开放、无邮箱验证（仅有查重限流）；站点一旦被扫到即可被灌垃圾，面试官看到的"第一眼"可能不是演示数据。
- **缓解（三选一，需拍板）**：
  - (a) 上线前加**注册开关**（一个 ENV，演示站默认关）← 推荐 —— ✅ 已于 2026-09-27 实现（`REGISTRATION_ENABLED`，默认 true；关闭时接口 40304、注册页显示"暂未开放"，验收 `verify-v04-regswitch.py`）
  - (b) 邀请码注册
  - (c) 开放 + 把 `seed-demo.py` 当"重置按钮"（幂等可重灌）
- **Owner**：你拍板 + 我实现（(a) 是小改动） · **期限：部署前**

### 🚧 T0-3 AI key 决策悬空 → 演示亮点变缺口（30 分钟内可决）
- **事实**：`AI_API_KEY` 为空时问答永远 `NO_KEY` 降级。面试场景下，要么充值（`AI_DAILY_BUDGET` 自带全站闸门），要么把**降级矩阵设计本身**当作演示点（"降级不报错"恰恰是亮点，DEMO 话术已含）。
- **缓解**：拍板二选一；若充值：日预算 ≤2000 + 用 `t_ai_answer_log` 对账。
- **Owner**：你 · **期限：部署前**

### 🚧 T0-4 跨境线路与首屏体验（launch-blocking）
- **事实**：内地不可备案 → 走香港（DEPLOY §1 已论证）；但非优化线路从内地访问可能"能开但慢"；首屏为几 MB 静态资源（无 CDN）。
- **缓解**：挑**大陆优化线路**；部署后用**手机 4G 实测首屏**（DEPLOY §5 已列入流程）；若慢：Caddy gzip（方案 B 自带）、必要时再压 Vite 产物。
- **Owner**：你（选机器）+ 我（陪测） · **期限：部署当天**

## Elephants（没人说出口的忧虑）

1. **"上线"的成功标准从未定义** —— 面试展示（成功 = 面试官点开 + 顺着讲 10 分钟）VS 真实运营（成功 = 注册 / 发帖 / 留存），两条路的资源分配完全不同。建议先写死一句话（[GTM.md](./GTM.md) 给了两套 KPI 模板）。
2. **"找回密码 / 邮箱验证"不存在** —— 通读认证面：只有登录 / 注册 / 改密 / 刷新，未见找回流程。演示无妨；真拉用户后第一条反馈大概率是"密码忘了怎么办"。先定站点定位，再决定补不补。
3. **"AI 写了多少"的问答预案** —— 6A 产物 + 747 断言 + 审计备注就是最好的回答（过程可见）；面试前把 TASKS 备注区翻一遍（DEMO 话术已给指引）。
4. **UGC 合规边界** —— 公开 + 开放注册 = 站主对访客内容有基本责任；T0-2 的"关闭注册"同时也是合规缓解。
