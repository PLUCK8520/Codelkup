# 3 分钟演示脚本（Codelkup）

> 用途：面试/演示时按这个顺序点，**3 分钟内**把"工程能力"讲出来 —— 不是把功能全点一遍。
> 前置：站点已部署（`deploy/deploy.sh --seed --verify` 跑过），打开 `http://<站点>/`。
> 演示账号：`ab@codelkup.dev` / `Codelkup@Demo2026`（见 DEPLOY.md §5；**别用管理员账号演示**）。

## 演示前的 30 秒检查（不占正式 3 分钟）

```bash
python deploy/verify-deploy.py --site http://localhost:8090   # 22 项全绿再开始
```

- 若站点**没配 AI key**：AI 环节会显示"AI 暂未启用（未配置模型密钥）"——**这也是要演示的一部分**（见 0:45 的话术），不用临时配 key。
- 浏览器先登录好、把首页开着，避免现场输密码。

## 时间轴

### 0:00 — 0:30 ｜ 首页与检索：先说"数据是真的"

| 操作 | 说这句话 |
|---|---|
| 打开首页（热门 tab），手指停在列表上 | "一万帖的压测数据在库里，热度分是每 5 分钟一条 SQL 全量重算的 —— `score` 索引在 EXPLAIN 里能直接看到命中。" |
| 顶部搜索框搜 `虚拟线程`，点进任意一条 | "MySQL **ngram** 全文索引，没上 ES。单字搜不到时走 LIKE 降级兜底 —— 为什么这么选，我写在 DEV-DOC 的检索章节里。" |

### 0:30 — 0:45 ｜ 发帖：顺手演"相似讨论提示"

| 操作 | 说这句话 |
|---|---|
| 点「创作 → 提个问题」，标题输入 `虚拟线程` + 几个字，**停 1 秒** | "标题边打边查站内有没有人问过（去抖 800ms、**不调 LLM**：这件事检索就能回答，让模型重说一遍只是多花钱）。" |
| 点提示里的一条（**新标签页**打开） | "开新标签页是因为当前页还写着草稿 —— 一次点击不该带走用户没发出去的内容。" |

### 0:45 — 1:30 ｜ AI 闭环：重点讲"降级"与"引用"

| 操作 | 说这句话 |
|---|---|
| 在长帖详情页点正文上方的「✦ AI 摘要」 | "长帖先剥 Markdown、截到 6000 字再交给模型 —— 截断处会告诉模型'看到省略号别脑补后半篇'。" |
| 点顶栏「问 Codelkup」，问 `虚拟线程和平台线程有什么区别？` | "答案里的 `[1][2]` 是**真链接**，点进去就是依据的那篇帖子 —— 引用是后端按结构化 postId 返回的，前端**纯文本分段渲染**，全程没有 `v-html`。" |
| **（关键）** 若站点没配 key：指着"AI 暂未启用（未配置模型密钥）"这行 | "注意这里 —— 没配密钥时 AI 接口**不报错**：降级成'仅检索结果 + 一句人话'，站内内容照常可读。成本上还有三道闸门：用户 10 次/小时 → 结果缓存（同一问题不重复计费）→ 全站日预算。" |

### 1:30 — 2:10 ｜ 实时通道：让角标"自己动"

| 操作 | 说这句话 |
|---|---|
| 打开两个浏览器窗口：A 用 `ab@codelkup.dev`，B 用 `xiaoman@codelkup.dev`（或手机 4G 开一个） | "A 盯着顶栏，B 去评论 A 的帖子。" |
| B 评论后看 A 的铃铛角标（**3 秒内**自己 +1） | "走 SSE 推的，不是轮询。鉴权用**一次性 ticket**（60 秒、Redis GETDEL 消费）——票在 URL 上但用一次就作废。" |
| （可选）`docker compose exec frontend nginx -T | grep -A7 notifications/stream` | "nginx 上 must 关 `proxy_buffering`，否则事件会被憋住；这条在部署自检里是**真拉一次流**验证的。" |

### 2:10 — 2:40 ｜ 一致性：地道的"后端味"

| 操作 | 说这句话 |
|---|---|
| 点赞/收藏一篇帖子，刷新页面 | "计数是 Redis 实时增量 + MySQL 可重建基线；刷新后数字不会漂。" |
| 头像菜单 →「我的草稿」→ 点「继续编辑」 | "草稿是**本地 localStorage + 服务端草稿箱**双层：断网也在，换设备也在；进编辑器会取两侧较新的一份。" |

| 操作 | 说这句话 |

## 常见提问的 30 秒回答（背下来）

| 提问 | 回答骨架 |
|---|---|
| "为什么不用 ES / 向量库？" | 一万帖 + ngram 零依赖够用（有压测数据）；ngram 的两个真实短板我量过并写进文档（整句中文按短语匹配 → RAG 先拆 2-gram 词袋）。上 ES 是优化叙事，不是功能补全。 |
| "AI 挂了怎么办？" | 七种降级原因都返回 `code 0` + 可读文案（实测 TIMEOUT 在 8051ms 触发）；前端按 `degraded` 展示，**从来不报错**。 |
| "成本怎么控？" | 三道闸门 + 只缓存花过钱的结果；`t_ai_answer_log` 只记指纹不记原文，一天花了多少一条 SQL 查出来。 |
| "为什么不用 Spring AI？" | 默认没用（零框架依赖、超时与降级自控），但**同一接口下真加了一个可切换的 Spring AI 实现**：`AI_IMPL=spring-ai` 一键切，跑同一套 87 项断言同样全绿 —— 框架自带重试带退避，我把它显式关成 `maxAttempts=1`，否则失败路径会偷偷翻倍成本。判断做成对比，而不是口头结论。 |
| "单人项目怎么保证质量？" | 每个功能都有可复跑的脚本 + 每次改动都重跑回归；**结论必须有实测证据**，未验证项会明确写在 TASKS 备注里。 |
| "线上出问题你怎么发现？" | 四组自定义指标挂在关键路径上：SSE 连接数（只涨不跌=连接泄漏）、AI 调用分布（`result`/`reason` 标签，降级占比一眼可见）、热度分重算耗时与影响行数、计数重建偏差。`/actuator/prometheus` **只对容器网络开放**（按来源地址放行，不是 permitAll），nginx 对 `/actuator/` 直接 404 —— 脚本里用 `X-Forwarded-For` 冒充两种来源验过。 |
| "最得意的一处？" | SSE 一次性 ticket（票在 URL 上也不怕泄漏）+ 计数三处同源；以及"发现 UI 报失败时先查后端计数再谈 bug"这类排查纪律。 |
