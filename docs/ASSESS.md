## 1. S1~S11 逐项对照

### S1 热度排序真实生效 —— ✅ 通过
- 标准：高互动帖排在低互动旧帖之前；`EXPLAIN` 无 filesort。
- 证据：`verify-v03-score.py` **9/9**（高互动 score=10.0 / 零互动=1.0；`hot` 与 `latest` 给出**不同**顺序，证明 hot 不再是时间序伪装）；写入路径 `ScoreService` 定时全量重算（`PostMapper.recalcScores` 一条 UPDATE，含时间衰减）；`V7` 索引 `idx_hot(status,is_top DESC,score DESC,create_time DESC)`；1 万帖重算实测 **105ms / 影响 10207 行**（备注 31）。
- 结论：承诺兑现，且性能余量充足。

### S2 死字段清零 —— ✅ 通过
- 标准：`score` / `reputation` / `level` 都有写入路径且前端可见。
- 证据：`verify-v03-reputation.py` **17/17**（+2/-2、+3/-3、评论被赞 ±2、采纳 +15、**自赞被拒 40001**、重复采纳幂等、压到 49 后 +2 自动升 Lv.2）+ `ReputationServiceTest` 7/7；`verify-v03-questions.py` **21/21**（采纳率与手算一致）；前端 `UserProfileView` 展示 LevelBadge / 声望。
- 结论：三个字段均有真实写入与展示闭环。

### S3 收藏闭环 —— ✅ 通过（残渣已清零）
- 标准：可从「我的收藏」进入并回到原帖。
- 证据：`verify-v03-collections.py` **23/23**（倒序 / 分页无重复无遗漏 / size 越界 40001 / 未登录 40101 / 取消后消失；`EXPLAIN` 走 `idx_user_type`）；前端 `/me/collections` 路由 + 头像菜单入口；M2-9 浏览器实测（2 卡片、后收在前、点回 `/posts/20046`）。
- 残渣：`UserActionMapper.selectLikedPostIds`（零调用死方法）本轮已删除（备注 35）。
- 结论：闭环成立。

### S4 草稿不丢 —— ✅ 通过（含一条已知取舍）
- 标准：编辑中刷新浏览器，正文自动恢复。
- 证据：`verify-v03-draft.mjs` **60/60**（版本自愈 / scope 隔离 / 节流与 flush / clear 后不复活 / 合并规则与失败降级 / 恢复询问会话态）；M2-10 浏览器实测（输入 → 5s 落盘 → F5 → 弹「恢复草稿」→ 恢复内容完整；发布后草稿清空）；落盘链路：5s 节流 + `beforeunload` + 卸载 flush，`?resume=1` 静默恢复；会话态浏览器复测（真实旧草稿：关掉对话框 → 离开再进不再弹，见备注 36）。
- 取舍记录：**普通刷新走确认框而非静默**（`?resume=1` 仍为静默恢复）——S4 只承诺"能恢复"，口径达成；「恢复重复询问无会话态」这项遗留已于本轮关闭（备注 36：kept / restored + `scope·updatedAt` 指纹）。
- 结论：通过。

### S5 发帖支持粘贴截图 —— ✅ 通过
- 标准：粘贴后 ≤3s 出图并插入 Markdown；后端断言落盘且 URL 可访问。
- 证据：`verify-v03-upload.py` **27/27**（扩展名白名单 + 魔数双校验：`shell.jsp`→40004、5.5MB→40005；配额 200；替换旧文件清理；URL 经 nginx 可读——compose 自检亦断言）；M2-12 浏览器实测：**3.74MB 稠密图 → 357KB / 901ms**（≤3s ✓、<400KB ✓），纯文本粘贴不被拦截，重复粘贴体积一致；实现 `useImagePaste.ts`（仅剪贴板含图时接管 + 四级压缩档位）。
- 结论：通过（承诺的时间与体积双指标均达标）。

### S6 提问闭环 —— ✅ 通过（本轮补修一处显示缺陷）
- 标准：可筛「待解决」；个人主页可见采纳率。
- 证据：`verify-v03-questions.py` **21/21**（`solved` 仅对 `type=1` 生效；采纳后从待解决流转到已解决）；M2-15 浏览器实测（URL 筛选、徽标、采纳率 50% / —）。
- 本轮补修：问答页「共 N 个提问」原用列表 `total`，切 tab 时漂移（「待解决」下渲染成 2010 而非 2051）—— 改用 `/api/stats` 聚合后三 tab 恒定一致（浏览器实测，备注 35）。
- 结论：通过（含缺陷修复）。

### S7 通知实时 —— ✅ 通过（并超出原承诺）
- 标准：SSE 未读数 ≤3s 更新；断线自动回退轮询。
- 证据：`verify-v03-sse.py` **35/35**（ticket 一次性 GETDEL / 心跳 / B 评论 A 帖 3 秒内收到 `event: unread` 且与轮询接口逐值一致 / 连接上限淘汰最旧 / **改密后服务端立即关闭该用户全部长连接（F2：会话撤销即断流）** / **改密前签发的票改密后消费被拒（第三轮审计：撤销水位）**）；`verify-v03-sse-frontend.mjs` **19/19**（换票重连 / 退避 / 3 次失败转轮询 / stop 幂等）；compose 自检「经 nginx 收到流的第一帧」（证明 nginx 未缓冲）。
- 本轮增强：**通知列表**也随推送实时刷新（原仅角标）—— 浏览器实测 A 关注 B，B 停在通知页不刷新，**1.5s 内**列表出现新通知、角标同步；新增契约 `verify-v04-notify-live.mjs` 10/10。
- 结论：通过，且提前关闭了备注 22 的体验边界。

### S8 AI 回答 —— ✅ 通过

## 7. 归档经验（写入下一轮工作流）

1. **"静态审计 + 运行时对账"缺一不可**：intended-vs-implemented 能证到 S1~S10 的代码级承诺，但看不到**组合面**（筛选状态 × 计数行的渲染矛盾）——那只有把真实页面在多个状态下对账才能现形（缺陷 #1）。
2. **"自检必须跑在真栈上"第三次实证**：旧镜像 + `restart: unless-stopped` 复活的旧栈，会让"等健康通过"变成一次自我欺骗；纪律：**① `--build` 重建 → ② 等健康 → ③ 再自检**，一步都不能省（备注 29 / 34 / 35）。
3. **数字必须等于分项之和；摘要缺行一律按失败**（备注 33 的记账错误、备注 30 的空输出即失败；**备注 47 再实证一次**：备注 43 起把总数写成 729，而分项之和 519+208 只有 727 —— 按分项修正重算为 737，第三轮扩项后终值 **747**）。
4. **假绿的三种已知形态**：读取逻辑漏读（备注 31）、忘传 token 的自检（备注 34）、验证对象是旧版本（本轮 #4）。识别方法同一句：**每一行断言都要能被证伪**。
5. **注释里的"安全性声明"也是断言**（第三轮审计新增）：`CounterRebuildService` 曾注释声称"先 MySQL 后 Redis 即安全"，实则在重建窗口内存在丢增量路径 —— 写保证前先证明它成立，否则注释会把后来人一起骗过；已改写为如实描述（备注 49 第 12 项）。
6. **自检的"失败信息"必须能自证**（金路径脚本落地新增）：`data_of(...) or 0`、`... or -1` 这类兜底会把"瞬时失败"掩成合法值 —— 断言失败时打印的是 0，看的人和写的人都会误判成"业务真的返回 0"（金路径首跑 43/44 的两处误判就是这么来的）。全部改成打印 `status + 原始 body` 之后，失败原因一眼可判。
7. **"环境玄学"先做分层对照，再下结论**（见 §6 第 13 行）：四组（容器内 / PowerShell / Python × `localhost` / `127.0.0.1`）一测就定案 —— 靠"再试一次"能蒙对结果，但会**写错原因**，而错误的归因会污染后续所有判断（先前几轮正是如此）。
