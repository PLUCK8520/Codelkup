# GTM（上市）方案 — Codelkup（2026-09-27）

> 框架：pm-skill / gtm-strategy（渠道 → 信息 → 指标 → 分期 → 90 天路线）。
> ⚠️ 前提：先回答 PRE-MORTEM 的 Elephant #1 —— 本站按 **"作品集 / 面试"为主轨、真实用户为辅轨**；两轨共用同一部署，但渠道与指标不同。

## 0. 定位与一句话
- **定位**：把"可验证工程"当卖点的程序员社区 —— 713 条验收断言、6A 全过程文档、安全审计清零、AI 降级不报错。
- **对面试官**："这是一个 Java 全栈社区项目；但我更想聊的是：每个功能都有脚本证明、每个非显然决定都留了'为什么'。"
- **对用户**："一个干净、快、有实时通知的程序员问答与分享社区。"

## 1. 目标人群（先窄后宽）
| 轨道 | 人群 | 他们在哪 | 怎么触达 |
|---|---|---|---|
| 主轨 | 面试官 / 技术评审 | 简历、GitHub、面试间 | 简历放 `https://` 链接 + DEMO-3min 话术 |
| 主轨 | 同行开发者（口碑扩散） | 掘金 / V2EX / 即刻 / 社群 | 技术复盘系列文（材料现成：TASKS 备注） |
| 辅轨 | 早期真实用户 | 同上去 | 开放注册 + 邀请 20 人冷启动 |

## 2. 渠道（少而精，主轨优先）
1. **简历 + GitHub（P0）**：README 顶部放演示链接；About 一句话定位；置顶一条"架构与验收地图"。
2. **内容渠道（P0）**——把"备注"改写成系列文，一周一篇，篇尾挂演示站：
   - ① 计数一致性：Redis 增量 + 可重建基线（driftCount）
   - ② XFF 信任边界与伪造演练
   - ③ SSE 一次性 ticket + nginx 为什么必须不缓冲
   - ④ 安全审计五连修："半豁免"是怎么被审出来的（M-1 / L-1~L-4）
   - ⑤ 一次失败实验复盘：为什么 WSL 里的 redis 服务不了 Windows（TASKS 备注 45）
3. **社区投放（P1）**：V2EX「分享创造」、掘金、即刻 —— 标题讲"可验证"，不要罗列功能。
4. **冷启动（辅轨，P2）**：邀请 20 人（同学 / 群友），目标是把"发帖 → 通知 → AI"闭环跑出真实数据。

## 3. 信息（按受众分版）
- 对面试官：证据链（713 / 26 / 审计清零 / 6A 文档）+ 取舍表述（单机单点为什么不假装修）。
- 对同行：可复用的坑与解法（上面五篇）。
- 对用户：快、干净、实时（不谈架构）。
- **禁区话术**：不吹"生产级高可用"、不吹压测绝对值（PRE-MORTEM Paper Tigers 已列）。

## 4. 指标（先有 baseline，再谈优化）
| 轨道 | 北极星 | 首月支撑指标 |
|---|---|---|
| 主轨（面试） | 面试转化 | 链接被点开数（nginx 日志粗估）、面试中被追问链路细节的次数 |
| 辅轨（用户） | 周活跃发帖人数 | 注册数、发帖/回答数、次日回访、通知点击率 |

## 5. 分阶段计划
- **T0（上线日）**：部署 + 4G 金路径走查 + 简历 / GitHub / 朋友圈更新
- **T+1~7**：发第一篇复盘文；观察漏斗（注册 → 发帖 → 回访）
- **T+2~4 周**：第二 / 三篇文 + V2EX 投放；辅轨拉 20 人
- **T+30**：复盘渠道与内容数据，决定辅轨去留

## 6. 90 天路线（轻量）
- **30 天**：内容 ×3 + 真实会话 ×20；视辅轨结论补"找回密码"等真运营缺口
- **60 天**：按用户反馈做 1 个"用户要的"小功能（用优先级框架筛）
- **90 天**：要么辅轨做出小而有生气的社区（目标：周 10 有效帖），要么把重心收回简历主轨 —— 都是成功

## 7. 风险与合规（点回 PRE-MORTEM）
- 内容污染 / UGC 责任 → 注册策略（T0-2，关闭注册同时是合规缓解）
- 跨境访问体验 → T0-4 缓解后仍有残留 → 对外口径明确"演示站"
- 宣传方式 → 内容为主、硬广为零，与"可验证工程"人设一致
